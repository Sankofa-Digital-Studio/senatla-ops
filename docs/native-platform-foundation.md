# Senatla Ops native platform foundation

## Decision

Senatla Ops uses the permanent application identifier `za.co.senatlatrading.ops` on Android and iOS. The generated native projects are committed because native OCR, scanner configuration, permissions, tests, and release settings are product code.

## Supported baseline

- Android: minimum SDK 24, compile and target SDK 36, Java 21 in CI.
- iOS: minimum iOS 17, Swift Package Manager, unsigned simulator builds in CI.
- Browser baseline: Angular 22 widely available baseline dated 2026-05-07.
- Web assets: generated by `npm run build` and synchronized with `npx cap sync <platform>`.

## Local verification

Android requires Android Studio, Android SDK 36, and JDK 21:

```text
npm ci
npm run build
npm run native:sync:android
cd android
./gradlew assembleDebug
```

iOS requires macOS and a supported Xcode release:

```text
npm ci
npm run build
npm run native:sync:ios
xcodebuild -project ios/App/App.xcodeproj -scheme App -configuration Debug -sdk iphonesimulator -destination "generic/platform=iOS Simulator" CODE_SIGNING_ALLOWED=NO build
```

## Signing boundary

CI in this slice builds debug/simulator artifacts without release signing. Production signing requires externally managed values and files:

- Android upload keystore, alias, keystore password, and key password.
- Apple Developer Team ID, App Store Connect issuer and key IDs, private API key, distribution certificate, and provisioning profile.

Keystores, certificates, provisioning profiles, service configuration files, and passwords must remain in the CI secret store. They must never be committed or copied into journey documents.

## OCR dependency boundary

OCR-0 does not add an OCR SDK. The next slice introduces a stable TypeScript scanning contract. Android ML Kit and Apple Vision/VisionKit implementations will be added only after that contract is tested.

## Release gates

1. Web build succeeds before native synchronization.
2. Android debug compilation succeeds on Linux CI.
3. iOS simulator compilation succeeds on macOS CI.
4. Release signing remains disabled until store identities and secret ownership are approved.
5. No native OCR dependency is accepted without offline, privacy, licence, and maintenance review.
6. Android application backup remains disabled and FileProvider sharing is limited to the dedicated capture cache.
7. Android release shrinking, version allocation, store signing, and a committed Swift dependency resolution remain release-stage gates; OCR-0 proves unsigned debug/simulator builds only.

## Install-script trust

The repository allowlist is exact-version scoped. `esbuild` supports Angular compilation; `@parcel/watcher`, `lmdb`, and `msgpackr-extract` build optional native performance modules; Cypress installs the pinned browser-test binary. Version changes return to an unapproved state for review rather than inheriting trust.
